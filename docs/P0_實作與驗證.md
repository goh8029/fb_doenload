# P0 實作與驗證紀錄

日期：2026-10-26（Asia/Taipei）｜版本：0.1.0｜執行：Codex

## 決策與範圍

依使用者指示做電腦端，沿用需求文件的 Windows Chrome MV3；控制頁參照「靜態介面.html」的拾光、午夜深藍、側邊導覽、選取檢視與確認視窗。沒有更改原需求或刪除原型。現階段只實作 P0 必需的實驗流程，不宣稱正式支援全部媒體。

專案原本僅有六份開發文件與一個靜態原型；沒有可沿用的程式碼或 Git 工作目錄，父層及專案內未發現 AGENTS.md。環境未在 PATH 提供 Node／npm／git，故於專案忽略目錄 .tools 安裝官方 Node 壓縮檔並核對 SHA-256，沒有全域安裝或修改系統 PATH。

## 檢查紀錄

- `pnpm build`：TypeScript 與兩階段 Vite 打包，實際結果見下方更新。
- `pnpm test`：來源白名單、身份歧義、Windows 檔名、串流、截短、HTML、429、取消、卡住及中斷紀錄；僅受控測試，不等同 TEST-006／007。
- `pnpm test:browser`：獨立 Chromium 核心設定檔載入 dist，受控 Facebook 網址 fixture 驗工作分頁／控制頁路由；不使用使用者帳號，不能算真實 Facebook 來源驗證。
- 瀏覽器原生目錄選擇器、授權撤銷、真實 CDN 與音軌需使用者已登入的 Chrome 實測。自動化 fixture 的目錄替代為瀏覽器沙盒，不能當成原生授權證據。

### 本次實際結果

環境：Windows 11 Home 10.0.26300、Node 24.22.1、pnpm 12.15.0、Edge 156.0.4314.42。此次未做效能壓測，不宣稱 p95 或記憶體上限已達標。

| 檢查 | 結果 | 證據與範圍 |
|---|---|---|
| pnpm frozen lockfile 安裝 | 通過 | pnpm 12.15.0；pnpm-workspace.yaml 明確允許 pnpm 本身的安裝腳本 |
| TypeScript／Vite 建置 | 通過 | dist/manifest.json、background.js、content.js、controller.html 與本機 assets |
| 單元與受控串流／提交測試 | 35 項通過 | test-results/unit.json；3 份測試檔，含提交失敗、唯一目錄及 URL 不落地 |
| MV3 載入與控制頁 | 通過（Edge Chromium 核心） | test-results/browser.json；獨立空白 profile，不使用登入資料 |
| 桌面／窄視窗與導覽 | 通過 | test-results/controller-desktop.png、controller-narrow.png；無 JS pageerror |
| 工作頁／目標／樣本／確認取消 | 通過（受控 fixture） | 原頁保留、session 路由、單樣本選取，取消後沙盒目錄無檔案 |

測試版 Chrome 下載速度不足，已停止兩個下載程序，改用現有 Edge 獨立測試設定檔完成自動化；未修改使用者瀏覽器設定。重新執行同樣測試可設定 `TEST_CHROME_PATH` 為 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` 再執行 `pnpm test:browser`。不設定時使用 Playwright 管理的 Chromium，需先安裝。

TEST-001 的建置／受控載入子項通過，Chrome 手動載入子項待驗；TEST-002／004／008 僅受控子項通過；TEST-005 原生授權與 TEST-006／007 真實媒體未執行。其他 TEST 不因原型已有相似 UI 而視為通過。DEV-001–007 仍為 P0 部分實作／待實測，DEV-008 關卡未通過。
