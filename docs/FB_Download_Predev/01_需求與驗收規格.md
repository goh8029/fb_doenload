# 需求與驗收規格
版本：1.0｜2026-10-24｜開發前設計，尚未實作驗收

預定專案：`D:\尚\side project\codex\FB_Download`

依據 Facebook_Downloader_Spec_v1.md v1.1 及使用者最新需求。此四份文件配套使用，原規格保留作需求來源。技術能力與版本待 P0 實測，未通過不得宣稱支援。

## 1 產品與邊界
Windows Chrome Manifest V3 擴充功能，沿用 FB 官方登入及原生頁面。下載目前登入者實際有權看到且工具支援的照片與影片。首版只有一鍵完整下載、勾選增量下載。無自架後端、無本機或雲端 DB、無遙測或背景監測。使用本機 JSON 索引及快照，不算建立 DB。

不含 EXE、APK、廣告、付款、會員、排程或權限繞過。不保證取得帳號全部歷史內容，未支援與掃描失敗必須揭露。

## 2 需求對照
| ID | 功能 | 行為與驗收 |
|---|---|---|
| R01 | FB 入口 | 支援的自己／他人頁有 FB 下載入口；混合頁及登入頁提供狀態 |
| R02 | 工作分頁 | 另開原來源 URL 的真正 FB 頁，加入工具 UI，保留原分頁；不 iframe 嵌入 FB |
| R03 | 目標辨識 | 顯示目標名稱、穩定 ID、來源；不明就要求選定，不擅自猜成登入者 |
| R04 | 一鍵下載 | 選根目錄、最後確認後，掃描全部可見且支援分類，逐批下載 |
| R05 | 完整批次 | 每次新時間戳批次，重新取得本次範圍，不刪或覆寫舊批次 |
| R06 | 勾選下載 | 工作頁照片／影片直接帶勾選框，不另切模式；按下載已選項目提交 |
| R07 | 父子選取 | 勾相簿／分類包含全部未載入子項；可排除個別項，父層顯示三態 |
| R08 | 選取保留 | 同目標跨分類保留，不同目標隔離；全選已載入與全選分類明確區分 |
| R09 | 右側檢視 | 相簿子項、選取及進度側欄可收合，與主畫面同步 |
| R10 | 增量下載 | 同媒體同品質且實體完整才跳過，遺失、零位元組或部分檔補下 |
| R11 | 保存層級 | 保留來源分類／相簿；跨分類允許磁碟副本，同任務盡量只傳輸一次 |
| R12 | 最後確認 | 兩模式都確認目標、模式、範圍與根目錄；取消不下載媒體 |
| R13 | 佇列控制 | 單檔卡住先延後，其他繼續；有限重試，可暫停、恢復及取消 |
| R14 | 真實進度 | 階段、數量、速率、可靠時的 ETA；未知總數不跑假百分比 |
| R15 | 結果摘要 | 成功、跳過、失敗及來源缺口分列，處理完成不等於全部成功 |
| R16 | 本機安全 | 授權目錄 JSON 索引，不收帳密、Cookie 或遙測，不越界寫入 |

## 3 UI 與確認
主區保留原生 FB 導覽，新增工具列、卡片勾選及可收合側欄。勾選事件不能觸發原卡片點擊；不同頁面重渲染不能產生重複按鈕。窄畫面改抽屜，直接媒體頁不強制空側欄。未展開相簿顯示「整個相簿，數量待掃描」。

下載可開擴充功能控制頁，透過「選擇資料夾」明確手勢取得授權，再最後確認。跨視窗可能多一次點擊，P0 驗證。確認時數量未知就寫掃描後確認，不捏造數字。

## 4 檔案規則
完整：根／目標名_ID／完整下載_時間戳／來源分類／相簿名_ID／媒體ID_品質.副檔名。
勾選：根／目標名_ID／勾選下載／來源分類／相簿名_ID／媒體ID_品質.副檔名。

來源沒有的層級略過。跨分類同媒體仍需建立各目的路徑；可共用一次網路取得後本機複製。勾選可核對同根歷次索引並使用可信完整副本，避免再連網。索引與磁碟都核對，不能僅信同名或下載紀錄。未知同名不默默覆寫；不因來源刪除而刪本機。

## 5 待測非功能目標
| 項目 | 初始目標 |
|---|---|
| 自有 UI | 1,000 筆清單勾選／切換 p95 ≤ 200ms，記錄環境 |
| 併發 | 下載初始 3，可調 1–4；單目標掃描 1 |
| 卡住 | 30 秒無新增位元組則延後，正常傳輸大影片不按固定總時長截斷 |
| 重試 | 初次外最多 2 次，非阻塞退避，過期連結重新解析 |
| 進度 | 執行中約每秒更新；總數未知用不定長進度 |
| 資源 | 有界佇列、背壓、串流與縮圖按需載入，上限由 P0 決定 |

不保證固定 Mbps。來源限制時暫停並說明；ETA 樣本不足顯示估算中。流程見 02，設計見 03，驗收見 04。
